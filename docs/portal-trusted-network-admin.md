# Trusted lab and VPN admin access

This path lets an approved Artisan lab or VPN exit IP reach the portal without
an individual Cloudflare Access email login. It does **not** grant immediate
admin access: the portal requires the shared master password and creates a
signed, IP-bound session that expires after eight hours.

## Required application configuration

Set all three production environment variables in Vercel:

- `PORTAL_TRUSTED_NETWORK_IPS`: comma-separated public egress IP addresses.
  Pacific Artisan Lab and the observed Artisan VPN exit currently use
  `96.76.102.241`.
- `PORTAL_TRUSTED_NETWORK_PASSWORD_HASH`: the scrypt hash generated by the
  credential helper. Never store the clear-text master password in Vercel or
  source control.
- `PORTAL_TRUSTED_NETWORK_SESSION_SECRET`: a separate random secret of at least
  32 characters.

Generate a new master password, password hash, and session secret with:

```bash
node scripts/generate-portal-trusted-network-secrets.mjs
```

Store the printed master password in the approved password manager. Add only
the hash and session secret to Vercel.

## Required Cloudflare Access policy

The application change alone does not skip Cloudflare's email screen. In the
existing portal Access application, add a narrowly scoped **Bypass** policy:

- Policy name: `Artisan labs and VPN - master password path`
- Action: `Bypass`
- Include: an IP list containing each approved lab/VPN public egress address
- Do not use `Everyone`, an email wildcard, an ASN, or a broad residential CIDR

Cloudflare evaluates Bypass before normal Allow policies. Bypass traffic does
not receive a Cloudflare identity and is not written to the Cloudflare Access
log, so the portal re-authenticates it with the master password and records the
resulting admin requests in the existing portal access log.

Use the zone's available rate-limiting rule for
`/api/portal/network-access/session` if that rule is not already committed to a
higher-priority endpoint. Even with rate limiting, keep the generated
high-entropy master password instead of choosing a short shared password.

## Verification before production enablement

1. Keep the policy disabled while the preview deployment is tested.
2. From an approved lab/VPN connection, confirm the public address is in the
   configured list.
3. Enable the IP-only Bypass policy and open `/portal` in a private window.
4. Confirm the branded master-password screen appears without an email login.
5. Confirm a wrong password stays blocked and a correct password reaches the
   Admin Portal.
6. Confirm `/portal/admin/access-log` records the synthetic identity
   `lab-vpn-admin@trusted.artisan.invalid` and the correct client IP.
7. Confirm **Sign Out** clears the session and returns to the password screen.
8. From a non-approved network, confirm Cloudflare still requires the normal
   email sign-in and the master-password screen is unreachable.
9. Confirm the direct Vercel deployment hostname cannot use a caller-supplied
   `cf-connecting-ip` header to reach the password path.

If an approved public IP changes, update both the Cloudflare IP list and the
Vercel environment variable before removing the old address.
